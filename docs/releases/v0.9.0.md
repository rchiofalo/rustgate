## Highlights

374 first-parent merges since v0.8.0 (April 12 → May 9, 2026). Workspace went from **18 to 32 crates** with no cycles. **Zero panics across 75M+ fuzz iterations** on the eight new wire-format codecs.

## Phase D — workspace refactor (5 PRs)

Extracted `rustgate-archive`, `rustgate-metrics`, `rustgate-tls`, `rustgate-admin`, and `rustgate-router` from `rustgate-core` / `rustgate-server` / `rustgate-transport`. Compile parallelism improved; the TLS + routing feature matrices now scope to their own crates. Federation, NATS, MQTT, WebSocket, HTTP, and the new bridge / codec crates all consume the routing engine directly without the TLS feature matrix tax.

## Breaking changes

None to the wire formats or runtime config. Crate-level moves only:

- `rustgate_core::encrypted::*` → `rustgate_archive::encrypted::*`
- `rustgate_core::audit_chain::*` → `rustgate_archive::audit_chain::*`
- `rustgate_server::archive::*` → `rustgate_archive::archive::*`
- `rustgate_core::metrics_util::*` → `rustgate_metrics::*`
- TLS / cert / OCSP / SPIFFE / TCP listener types: `rustgate_transport::*` → `rustgate_tls::*`
- HTTP management server + ACL API: `rustgate_server::*` → `rustgate_admin::*`
- Routing engine + ACL + dedup + store-and-forward + position cache + replay + throttle + quota + obligations: `rustgate_transport::*` → `rustgate_router::*`

The `rustgate-transport` crate is now scoped to codecs, UDP, hardware-identity glue, and the egress envelope. Downstream consumers update import paths only — no API behavior change.

## Upgrading from v0.8.0

The crate moves listed under "Breaking changes" above are mechanical. If you import directly from a Rust dependent, the compiler will tell you which import paths to update; the symbol set is unchanged.

If you build with `--features fips`, `--features post-quantum`, `--features ocsp`, or `--features spiffe`, point those flags at the new `rustgate-tls` crate (or rely on the `rustgate-server` passthrough features which already do).

If you write Cedar policies with `action: "Route"`, see the new CJADC2 routing-policy docs and the `@route` annotation syntax.

If you operate a multi-tenant deployment, see the new docs on per-tenant archive subdirectories and the opt-in NATS subject prefix.
